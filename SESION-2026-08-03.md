## 2. Corrección bug RLS / Edge Runtime

**Problema:** El middleware de Next.js (Edge Runtime) fallaba silenciosamente al consultar `profiles` con el cliente de sesión estándar, porque la política RLS recursiva de "Admins ven todos" devolvía `null` en vez de lanzar error. Esto causaba redirect al mapa en vez de entrar al panel admin, y mostraba plan "free" en `/cuenta`.

**Solución:** Usar `createClient` con `SUPABASE_SERVICE_ROLE_KEY` (service role, bypass de RLS) en todos los contextos server-side donde se lee el perfil:

- `src/lib/supabase/middleware.ts` — admin check en proxy
- `src/app/admin/layout.tsx` — verificación de rol en layout admin
- `src/app/cuenta/page.tsx` — lectura del perfil del usuario

**Archivos modificados:**
- `src/lib/supabase/middleware.ts`
- `src/app/admin/layout.tsx`
- `src/app/cuenta/page.tsx` — también agrega badge "Administrador" y oculta banner de upgrade para admins

**Antes:** Las concesiones solo cargaban desde zoom 10 (nivel ciudad).

**Después:** Cargan desde zoom 7 (nivel región/país), con ajuste dinámico:

| Zoom | Límite de registros | Estilo |
|------|---------------------|--------|
| ≥ 10 | 2.000 | Trazo 1.5px, fillOpacity 0.22 |
| 9 | 800 | Trazo 0.6px, fillOpacity 0.35 |
| 7–8 | 300 | Trazo 0.6px, fillOpacity 0.35 |
| < 7 | — | Mensaje "Acerca el mapa para ver concesiones" |

**Archivo:** `src/app/mapa/MapClient.tsx`

## Notas técnicas importantes

- **Next.js 16 renombra Middleware → Proxy:** el archivo es `src/proxy.ts`, no `middleware.ts`.
- **RLS recursiva falla en Edge Runtime:** siempre usar service role key para consultas de perfil en server components, layouts y proxy.
- **Variables de entorno Vercel:** `SUPABASE_SERVICE_ROLE_KEY` solo estaba en Production. Se copió manualmente al `.env.local` desde el Dashboard de Supabase → Project Settings → API.
- **Esri World Imagery:** `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}` — tiles satelitales gratuitos sin autenticación.
